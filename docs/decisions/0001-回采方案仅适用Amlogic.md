# ADR 0001：屏幕回采走厂商 screencontrol，并限定只支持 Amlogic

- 状态：已接受
- 日期：2026-11-06

## 背景

目标是把电视画面推到浏览器。候选方案：

| 方案 | 视频画面 | 依赖 | 结论 |
|---|---|---|---|
| `adb screencap` | ❌ 全黑 | 无 | 不可用 |
| `MediaProjection`（AOSP 官方） | ❌ 全黑 | 无 | 不可用 |
| `scrcpy` | ❌ 全黑 | 无 | 不可用 |
| HDMI 采集卡 | ✅ | 硬件 | 可行但要买设备 |
| 抓原始流 | ✅ | 需要解 URL / 中间人 | 只能看同一频道，不是"电视画面" |
| **厂商 `screencontrol` 回采** | ✅ | **Amlogic + root** | **采用** |

全黑的原因：解码后的画面走**独立硬件视频层**，不经 `SurfaceFlinger` 合成，
所以任何基于 `SurfaceFlinger` 的截屏都只能拿到 UI 层。详见 [HOW-IT-WORKS](../HOW-IT-WORKS.md) 第 1 节。

## 决策

采用**厂商 `screencontrol` 硬件回采**（VDIN 回采显示管线输出），
明确**只支持 Amlogic 芯片 + 已 root 的电视**。

## 后果

**正面**
- 能拿到完整画面（含视频层），这是唯一纯软件可行的路
- 支持硬件缩放，缩小分辨率不额外花钱
- 不需要额外硬件

**负面**
- 强依赖 Amlogic 私有服务，换芯片平台完全失效
- 必须 root
- 帧率上限约 18 fps（厂商接口固定开销）
- 无鉴权 / 无 TLS，只能内网用

## 备选方案保留

HDMI 采集卡仍然是最稳的兜底方案（任何电视都适用，无 root 要求），
成本约一两百元。如果将来需要支持多品牌电视，优先考虑它而不是逆向各家私有服务。
