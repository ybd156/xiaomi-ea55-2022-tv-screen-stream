# ADR 0004：遥控端点必须带令牌

- 状态：已接受
- 日期：2026-11-14
- 关联：[API.md](../API.md)「遥控」、[AGENTS.md](../../AGENTS.md) §1 §2.4

## 背景

原来这个服务只能**看**（`/raw` `/stream` `/snap` `/pcm`）和做两件电源操作（`/wake` `/sleep`），
所有端点都没有鉴权。现在要加**遥控**：`/key?code=DPAD_UP` 直接往电视注入按键。

这把风险抬了一个量级：

| | 加遥控之前 | 加遥控之后 |
|---|---|---|
| 同网段任意主机 | 能看画面、听声音、开关电视 | **能完全操作电视**（导航、进设置、装应用…） |
| 你浏览的任意网页 | 能触发 `/sleep`（副作用型 CSRF） | **能连按按键**：`<img src="http://tv:8899/key?code=DPAD_DOWN">` × N |

第二条是新出现的：浏览器允许跨源发"简单请求"，但**不允许读响应**。所以只要端点不校验任何
只有同源页面才拿得到的东西，任何网页都能盲发按键。这是加遥控前必须解决的事。

## 决策

1. **只有 `/key` 和 `/text` 要求令牌**，其余端点维持现状（不破坏已有脚本和 VLC/OBS 用法）。
2. 令牌来源：默认进程启动时随机生成（6 字节 hex），**注入到网页 HTML**；可用
   `-Dtvss.token=xxx` 固定，便于脚本调用。
3. 令牌**不写日志、不进仓库**（AGENTS.md §2.3）。要取就从页面源码里取。
4. 按键走**白名单**（`KEYS` 表），只放遥控器上有的名字，不接受任意键码。
5. **`POWER`(26) 不进白名单**：它是开关不是唤醒，盲发会把醒着的电视关掉（AGENTS.md §2.4）。
   电源只走 `/wake` `/sleep`，它们内部先查 `dumpsys power`。
6. 文字输入只接受可打印 ASCII，空格转成 `%s`，其余特殊字符丢弃——`input text` 会自己解释
   一部分字符，不做净化等于给命令解释器留口子。

## 威胁模型（写清楚边界，别夸大）

| 攻击者 | 令牌能挡住吗 |
|---|---|
| 你访问的恶意网页（跨源盲发按键） | ✅ 挡住 —— 它读不到本页 HTML，拿不到令牌 |
| 局域网内的其它主机 / 已连上的设备 | ❌ 挡不住 —— 它可以 `curl /` 把令牌读出来 |
| 公网（端口被映射出去） | ❌ 挡不住 —— 同上 |

所以令牌解决的是"**顺手被网页坑**"，不是"**有人恶意控制**"。后者只能靠网络隔离：
不要把 8899 映射到公网，不要和不可信设备同网段（包括 ZeroTier 这类组网）。

## 被否决的方案

| 方案 | 为什么不行 |
|---|---|
| 全部端点都加令牌 | 会打断现有用法（VLC 拉 `/stream`、OBS、`/stats` 监控），收益不抵成本 |
| 完全不加令牌 | 任意网页可盲发按键，等于把电视控制权交给互联网 |
| 用 HTTP Basic 认证 | 浏览器弹框、VLC/OBS 支持不一，且明文密码在无 TLS 下更糟 |
| 只允许本机/白名单 IP | 手机、平板都要用，维护成本高；且 NAT 后不可靠 |
| 用 POST + CSRF token | 更规范，但现有服务是手写 HTTP/1.0、只做 GET，改造面大；令牌已能覆盖主要威胁 |

## 后果

**正面**
- 新增能力不扩大"被网页坑"的攻击面；
- 按键有白名单，不会因为拼错名字就发出奇怪键码；
- 电源语义保持单一入口（`/wake` `/sleep`），不会出现两个地方抢着改电源状态。

**负面**
- 脚本调用要多带一个 `t=` 参数（可用 `-Dtvss.token` 固定成好记的值）；
- 令牌在页面 HTML 里，任何能读页面的人都能拿到——这决定了它只是"防顺手"，不是"防恶意"；
- 每个按键 fork 一个 `input` 进程（约 30–80 ms），连按会有轻微延迟，暂未做批处理。
